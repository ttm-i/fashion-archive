# Fashion Archive 初版仕様書

## 0. 文書情報

- 文書名: Fashion Archive 初版仕様書
- 版: 0.1
- 状態: 初版実装前の合意仕様
- 作成日: 2026-10-21
- 対象端末: iPhone 17
- 動作確認基準: iOS 27.0.1
- 配信候補: GitHub Pages

本書は、初版の実装範囲、データ構造、画面、保存、バックアップ、確認条件を定義する。実装中に変更が必要になった場合は、理由と影響範囲を記録してから本書を更新する。

## 1. 目的

Fashion Archiveは、所有している洋服やファッションアイテムを写真中心で記録し、自分のコレクションとして眺め、検索・分類・集計できる個人用PWAである。

家計簿ではなく、次の体験を重視する。

- 写真を主役にコレクションを楽しめる
- 購入直後でも少ない入力で登録できる
- 後から情報を追記・整理できる
- 通信できない場所でも通常機能を使用できる
- 長期間利用してもデータを安全に持ち出せる

## 2. 初版の基本方針

- iPhone専用として設計する
- アカウント、ログイン、サーバーデータベースは使用しない
- アイテム情報と写真はiPhone内に保存する
- 初回導入とアプリ更新を除き、通常利用はオフラインで完結させる
- 必要以上に機能を増やさず、登録・閲覧・検索・集計・バックアップを優先する
- 将来の項目追加で既存データを登録し直さなくてよい構造にする
- 外部API、アクセス解析、広告、外部CDNは使用しない

## 3. 対象外

初版では次の機能を実装しない。

- iPad向けレイアウト
- Android専用対応
- PC版データの本番移行
- 複数端末間の自動同期
- ユーザーアカウント
- ウィッシュリスト
- 素材・混率
- 採寸・サイズ比較
- タグ
- コーディネート管理
- 売却・譲渡・処分履歴
- 通知
- ダークモード

これらを後から追加できるよう、識別子、データ形式のバージョン、更新日時は初版から保持する。

## 4. 推奨技術構成

| 区分 | 採用候補 | 役割 |
|---|---|---|
| UI | React | 画面と状態を部品単位で管理する |
| 言語 | TypeScript | データ項目や処理の間違いを検出しやすくする |
| 開発環境 | Vite | Windowsでの開発・ビルドとGitHub Pages配信を簡素化する |
| 端末内データ | IndexedDB | アイテム、設定、画像をiPhone内に保存する |
| IndexedDB補助 | Dexie.js | 保存・検索・更新・データ移行を安全に扱う |
| オフライン | Service Worker | アプリ本体を保存し、オフライン起動を可能にする |
| スタイル | CSS Modules、CSS変数 | 独自デザインと保守性を両立する |
| テスト | Vitest、Testing Library、Playwright | 計算、画面、保存処理を自動確認する |
| 配信 | GitHub Actions、GitHub Pages | ビルドと公開を自動化する |

サーバー処理を必要とするフレームワークは使用しない。統計グラフは初版ではCSSまたは軽量なSVGで実装し、大規模なグラフライブラリは必須としない。

## 5. 機能要件

### 5.1 コレクション一覧

- 登録済みアイテムを写真中心の2列グリッドで表示する
- 各カードに表紙写真、ブランド、アイテム名、購入価格を表示する
- 情報が未登録の欄は、一覧上で不要なプレースホルダーを目立たせない
- 表紙写真がないアイテムには統一したプレースホルダーを表示する
- アイテムをタップすると詳細画面へ移動する
- お気に入りをカード上から切り替えられる
- アイテム数と現在の絞り込み結果件数を表示する
- スクロール位置を詳細画面から戻った際に可能な範囲で維持する
- 空の状態では、新規登録へ誘導する説明を表示する

### 5.2 検索・絞り込み

キーワード検索の対象は次の項目とする。

- アイテム名
- ブランド
- カラー
- 購入先
- メモ

絞り込み条件は次のとおりとする。

- カテゴリー
- ブランド
- 購入年
- 購入方法
- お気に入りのみ
- 購入価格の下限・上限

複数条件は同時に指定できる。条件の解除ボタンと、適用中の条件数を表示する。

並べ替えは次のとおりとする。

- 購入日の新しい順（初期値）
- 購入日の古い順
- 登録日の新しい順
- 名前順
- ブランド順
- 購入価格の高い順
- 購入価格の安い順

未入力値は、日付や価格による並べ替えで予期せず先頭に出ないよう末尾に配置する。

### 5.3 アイテム登録・編集

必須項目はアイテム名のみとする。写真や購入情報が未入力でも保存できる。

| 項目 | 形式 | 初期仕様 |
|---|---|---|
| アイテム名 | 文字列 | 必須、前後の空白を除去 |
| ブランド | 文字列 | 過去入力から候補表示、自由入力可 |
| カテゴリー | 選択 | 初期カテゴリーまたは追加カテゴリー |
| 写真 | 画像 | 0～3枚 |
| 表紙写真 | 画像参照 | 写真がある場合は必ず1枚 |
| サイズ | 文字列 | 自由入力 |
| カラー | 文字列 | 自由入力、過去入力から候補表示 |
| 定価 | 円、整数 | 0以上、未入力可 |
| 購入価格 | 円、整数 | 0以上、未入力可 |
| 購入日 | 日付 | 未入力可、時刻は保持しない |
| 購入方法 | 選択 | 未入力可 |
| 購入先 | 文字列 | 過去入力から候補表示、自由入力可 |
| メモ | 複数行文字列 | 未入力可 |
| お気に入り | 真偽値 | 初期値はOFF |

入力画面は次の4区分とする。

1. 写真
2. 基本情報
3. 購入情報
4. その他

購入情報とその他は折りたたみ可能にする。保存ボタンは画面下部に固定し、iPhoneのホームインジケーターと重ならないようにする。

編集内容が未保存の状態で戻ろうとした場合は、破棄確認を表示する。保存中の二重操作を防止し、保存に失敗した場合は入力内容を画面上に残す。

### 5.4 写真

- 1アイテムにつき最大3枚とする
- 写真ライブラリとカメラから追加できるようにする
- 先頭の写真を表紙として扱う
- 写真の並べ替え、表紙変更、個別削除を可能にする
- 4枚目を追加しようとした場合は、既存写真を削除する必要があることを表示する
- 詳細画面では左右スワイプで写真を切り替える
- 現在位置をドットまたは `1 / 3` の形式で示す
- 写真タップで全画面表示する
- 全画面表示ではピンチ拡大と閉じる操作を提供する
- 写真の縦横比を壊さない

写真は保存前に端末内で向き補正と縮小を行う。初期実装値は長辺2,048px程度、品質85%程度を候補とし、iPhone実機で文字・素材感・保存容量を比較して確定する。一覧用には別の軽量サムネイルを生成する。

圧縮後の画像をアプリ内の正本とし、元の巨大画像は保持しない。元画像はiPhoneの写真ライブラリに残る。

### 5.5 アイテム詳細

- 写真カルーセル
- お気に入り切替
- ブランド
- アイテム名
- 定価
- 購入価格
- 値引き額または値引率（両方の価格がある場合）
- カテゴリー
- サイズ
- カラー
- 購入日
- 購入方法
- 購入先
- メモ
- 編集ボタン
- ゴミ箱へ移動するボタン

未入力項目は空欄として並べず、項目ごと非表示にする。

### 5.6 インサイト

ゴミ箱内のアイテムはすべての集計から除外する。

| 指標 | 計算方法 |
|---|---|
| 所有アイテム数 | ゴミ箱を除く全アイテム数 |
| 総購入金額 | 購入価格が入力されたアイテムの合計 |
| 平均購入単価 | 購入価格が入力されたアイテムだけを分母とした平均 |
| カテゴリー別点数 | カテゴリーごとの件数 |
| カテゴリー別金額 | カテゴリーごとの購入価格合計 |
| ブランド別点数 | ブランドごとの件数 |
| ブランド別金額 | ブランドごとの購入価格合計 |
| 年別・月別金額 | 購入日と購入価格の両方があるアイテムの合計 |
| 購入方法別集計 | 購入方法ごとの件数と購入価格合計 |

購入日不明のアイテムは年別・月別集計に含めない。購入価格不明のアイテムは金額集計に含めないが、点数集計には含める。0円は有効な購入価格として扱う。

### 5.7 ゴミ箱

- 削除操作は即時の完全削除ではなく、ゴミ箱への移動とする
- 移動直後に「元に戻す」を表示する
- ゴミ箱画面で削除日時を確認できる
- 個別復元と、ゴミ箱を空にする操作を提供する
- 30日を超えたデータには整理を促す表示を出す
- 自動完全削除は行わない
- 完全削除時は写真も削除されることを明示して再確認する
- 使用中の画像が他アイテムから参照されていないことを確認してから画像を削除する

### 5.8 設定・マスターデータ

初期カテゴリーは次の7種類とする。

1. アウター
2. トップス
3. ボトムス
4. シューズ
5. バッグ
6. アクセサリー
7. その他

カテゴリーは追加、名称変更、並べ替えを可能にする。使用中カテゴリーの削除は、そのカテゴリーを使用するアイテムの変更先を指定するまで実行しない。

購入方法は次の5種類とする。

1. 実店舗
2. 公式オンライン
3. 総合オンライン
4. フリマ・中古
5. その他

購入先は自由入力とし、既存データから入力候補を表示する。

設定画面には次を含める。

- カテゴリー管理
- バックアップ作成
- バックアップ復元
- CSV出力
- ゴミ箱
- 保存容量
- 最終バックアップ日時
- アプリバージョン
- オフライン状態と更新状態

## 6. 画面構成と遷移

### 6.1 下部ナビゲーション

常設する主要画面は3つとする。

1. コレクション
2. インサイト
3. 設定

新規登録はコレクション画面右下のフローティング「＋」ボタンから開く。

```text
アプリ起動
  └─ コレクション
       ├─ 検索
       ├─ 絞り込み・並べ替え
       ├─ ＋ 新規登録
       │    └─ 保存 → 詳細またはコレクション
       └─ アイテム選択
            └─ 詳細
                 ├─ 編集
                 └─ ゴミ箱へ移動

インサイト
  ├─ 概要
  ├─ 月別・年別
  ├─ カテゴリー
  ├─ ブランド
  └─ 購入方法

設定
  ├─ カテゴリー管理
  ├─ データ管理
  ├─ ゴミ箱
  └─ アプリ情報
```

### 6.2 iPhone表示規則

- 縦向きを主として設計する
- 横向きでも操作不能にならないようにする
- ノッチ、Dynamic Island、ホームインジケーター用のSafe Areaを考慮する
- 最小タップ領域は原則44px以上とする
- 文字入力時に保存ボタンや入力欄がキーボードに隠れないようにする
- ブラウザ表示とホーム画面PWA表示の両方で破綻しないようにする
- ブラウザの戻る操作とアプリ内の戻る操作を整合させる

## 7. デザイン仕様

### 7.1 方向性

- セレクトショップの商品一覧と個人アーカイブの中間
- モノトーンを基本に、温かみのあるオフホワイトを背景にする
- 強調色はPC版を継承した控えめなコーラル系とする
- 写真、余白、タイポグラフィを主役にする
- 枠線や影を多用せず、情報の階層で整理する

### 7.2 初期カラートークン候補

- 背景: 暖色寄りのオフホワイト
- カード背景: ホワイト
- 主要文字: ほぼブラック
- 補助文字: 中間グレー
- 区切り線: 薄いウォームグレー
- アクセント: 落ち着いたコーラル
- 危険操作: アクセントとは区別できる赤

色コードは画面モックアップとiPhone実機確認後に確定する。

### 7.3 写真表示

- 一覧は正方形の写真領域を基本とする
- 初期表示は画像全体を切らない `contain` 相当を基本とする
- 写真のない余白には背景色を使用する
- 詳細画面では縦長・横長画像も全体を確認できるようにする

- アプリのデータ形式バージョン

## 9. 保存・オフライン仕様

- IndexedDBをユーザーデータの正本とする
- Cache Storageにはアプリ本体のみを保存する
- アプリ更新時にIndexedDBを削除しない
- データ形式変更は段階的なマイグレーションとして実行する
- マイグレーション失敗時は既存データを保持し、利用者へ復旧方法を表示する
- 保存は関連するデータをまとめて更新し、途中状態を残さない
- 容量不足時は保存失敗を明示し、写真削除またはバックアップを案内する
- 利用可能な環境では永続ストレージを要求する
- 保存使用量と推定上限を設定画面に表示する
- アプリ本体のCSS、JavaScript、アイコン、フォントはすべてオフライン利用できるよう同梱する

## 10. バックアップ・復元

### 10.1 完全バックアップ

バックアップファイル名は次の形式とする。

`FashionArchive_Backup_YYYYMMDD_HHmm.zip`

構成例:

```text
FashionArchive_Backup_20261021_2100.zip
  ├─ manifest.json
  ├─ items.json
  ├─ categories.json
  ├─ settings.json
  └─ images/
       ├─ <image-id>.webp
       └─ ...
```

`manifest.json`には次を含める。

- アプリ名
- バックアップ作成日時
- アプリバージョン
- データ形式バージョン
- アイテム件数
- 画像件数
- ファイル一覧
- 検証用情報

バックアップにはゴミ箱内のアイテムも含める。生成したファイルはiPhoneのファイルアプリやiCloud Driveへ利用者が保存する。

### 10.2 復元

- 対応するバックアップか確認する
- 必須JSONの存在と形式を確認する
- 画像件数と参照関係を確認する
- 復元前にバックアップ日時、件数、画像数を表示する
- 初版では「現在データを置き換える」方式とする
- 現在データのバックアップ作成を案内してから復元を確定する
- 検証完了前に現在データを変更しない
- 復元処理は可能な限り一括して実行し、失敗時は元の状態を維持する
- 新しい形式のバックアップを古いアプリで開こうとした場合は、上書きせずアプリ更新を案内する

### 10.3 CSV

CSVには写真を含めず、閲覧・集計用として次を出力する。

- アイテム名
- ブランド
- カテゴリー
- サイズ
- カラー
- 定価
- 購入価格
- 購入日
- 購入方法
- 購入先
- お気に入り
- メモ
- 登録日時
- 更新日時

Excelで開いた際の日本語文字化けを避ける形式を採用する。

## 11. PWA仕様

- ホーム画面追加用のアプリ名、アイコン、テーマ色を用意する
- standalone表示に対応する
- GitHub Pagesのサブパス配信に対応する
- 初回オンライン起動後、アプリ本体をオフラインで起動できるようにする
- オフライン中でも登録、編集、削除、検索、統計、バックアップを利用可能にする
- 更新がある場合は「新しいバージョンがあります」と表示する
- 編集中に強制更新しない
- 更新適用後も登録データと写真を維持する
- 公開URL変更前にバックアップが必要であることを運用手順へ記載する

## 12. プライバシーと安全性

- ユーザーデータと写真をサーバーへ送信しない
- アクセス解析を組み込まない
- 広告や外部トラッカーを組み込まない
- 実データ、バックアップ、実際の商品写真をGitリポジトリへ含めない
- GitHub Pages用の公開テストデータは架空データを使用する
- PC版データはローカル環境のテストにのみ利用する
- インポートするバックアップの内容をコードとして実行しない
- 表示する文字列を安全に扱い、HTMLとして解釈しない

GitHub Pages上のアプリ本体は公開される可能性があるが、IndexedDB内のユーザーデータは公開リポジトリには保存されない。

## 13. エラー・案内表示

最低限、次の状態を利用者に分かる言葉で表示する。

- 保存完了
- 保存失敗
- 容量不足
- 写真処理中
- 対応していない画像
- 写真3枚の上限
- バックアップ作成中・完了・失敗
- 復元内容の検証中・完了・失敗
- オフライン状態
- アプリ更新あり
- 検索結果なし
- データ未登録

エラーには専門的な例外名だけを表示せず、利用者が次に取る操作を併記する。

## 14. 品質確認

## 15. 初版の受入条件

次をすべて満たした時点で初版完成とする。

1. アイテムを写真なし、1枚、3枚の各状態で登録できる
2. 保存後にPWAを閉じて再起動してもデータが残る
3. オフラインで一覧、詳細、登録、編集、削除、統計を使用できる
4. キーワード検索と各絞り込みが正しく組み合わさる
5. 金額・日付の未入力データを含めても統計が破綻しない
6. ゴミ箱から復元できる
7. 完全バックアップからアイテムと全写真を復元できる
8. 復元失敗時に既存データを失わない
9. アプリ更新後も既存データが残る
10. iPhone 17、iOS 27.0.1で主要操作を実機確認できる
11. GitHub Pages公開物に実データや実写真が含まれない
12. 利用者向けに導入・バックアップ・復元手順が用意されている

## 17. 将来拡張時の原則

- ウィッシュリストは既存アイテムに状態フィールドを追加して扱う
- 素材は複数素材と比率を扱える別レコードとして追加する
- 採寸はカテゴリーごとに項目を定義できる構造にする
- 所有終了履歴を追加しても購入統計を失わないようにする
- 自動同期を追加する場合も、ローカル単独利用を維持できる設計とする
- データ形式を変更する場合は、古いバックアップを読み込める移行処理を用意する
